# 래티스 형식 v1 과 ltxm 래티스 편집기 — 설계 초안 1 (2026-10-29)

래티스 리깅 통합 설계안(`atlas-rig-unification-design-2026-10-27.md`) §17 에서 합의한 방향을 저장 형식으로 확정하고,
그 형식을 만들고 고치는 편집기를 ltxm 에 넣는 설계다. 소비 쪽(lbsvm-core 가이드, 9-slice, 길이 리그)은 편집기가
생긴 뒤에 붙인다. 코드 변경은 없다. 확정안이 아니며, 읽고 결정한 뒤 고친다.

## 0. 한 장 요약

- **형식.** 래티스 하나는 축 두 개(`lon`·`lat`)로 이루어진다. 축마다 다음을 갖는다.
  - `axis`: 텍스처 축과 + 방향(`"+x"`, `"-x"`, `"+y"`, `"-y"`)
  - `px`: 구간 경계선(픽셀 오름차순)
  - `seg`: 구간 성질. 값이 없으면(null) 늘림(`str`), 값이 있으면 고정(`fix`). 숫자는 고정 길이의 배율, 문자열은 크기
    변수 이름이다(§3-2)
  - `handles`: 손잡이(태그가 붙은 직선, 구간 경계와 위치가 달라도 됨)

  반전·미러선·별도 사각형 필드·물리 단위·기본 배치 값은 없다. 방향은 `axis` 가 정하고, 뒤집어 붙이기·좌우 대칭·단위·
  축척·기본 배치는 쓰는 쪽(연결)이 맡는다. 래티스는 그림에 관한 사실만 갖는다.
- **풀이.** 연결된 이웃 손잡이 사이에서 `fix` 는 길이를 유지하고 `str` 이 남는 길이를 나눠 갖는다. 규칙은 이것 하나이고,
  맞출 수 없는 경우는 진단으로 돌려준다.
- **옛 격자.** 같은 PNG 청크 안에 `lattices` 키를 새로 두고, 옛 `grids` 는 그대로 보존한다. 옛 소비자(lbsvm-core
  `LoadTextureMap`, S3000ABR)는 영향을 받지 않는다. 편집기는 옛 격자에서 래티스를 만드는 변환을 명시적인 조작으로 제공한다.
- **편집기.** ltxm 에 "래티스" 모드를 추가한다. 이미지 위에 선과 손잡이를 그리고, 래티스 위·왼쪽의 **자(ruler) 띠**를
  칠해 구간 성질을 정한다. 숫자 표로 정확한 값을 고치고, 미리보기 창에서 손잡이에 목표 값을 넣어 늘어난 모양과 진단을
  바로 본다. 되돌리기를 함께 넣는다.
- **코드.** 형식·검증·풀이·변환은 GL 없는 C 로 lbx-geo `lbx_lattice` 에 둔다(ltxm 과 lbsvm-core 가 같이 쓴다). 편집기
  UI 는 ltxm 에 새 파일로 두고, 기존 격자 편집 코드는 고치지 않는다.

## 1. 배경과 범위

- 계기: car.png 의 DPGL 격자는 승용차용 거리(0.5·1·3 m)가 그림 데이터에 직접 적혀 있어 트럭(1·3·10 m)에 쓸 수 없다.
  asset 수정은 저장 원칙(배포 고정 자산 / 차종·기기 값은 config 층)에 맞지 않는다. 설계안 §17-1.
- 합의된 원칙(§17-3·§17-4):
  - 선은 위치만, 구간이 성질을 갖는다. 핀(손잡이)은 태그가 붙은 직선이다.
  - 반전은 데이터 순서로 나타내지 않는다. 선 순서가 방향을 겸하면 구간이 고정된 정체성을 갖지 못한다.
  - 개별 요소를 단순하게 둔다. 래티스는 그림에 관한 사실만 갖고, 어떻게 붙이는가는 전부 연결이 정한다.
- 이 문서의 범위: 형식 v1, 1차원 풀이, 옛 격자와의 공존, ltxm 편집기. 연결(배치) 저장과 svmdemo 연결 UI 는 설계안
  §17-7 ② 를 따르며 여기서는 편집기 미리보기에 필요한 만큼만 다룬다.

## 2. 지금 ltxm 격자 편집기

`tool/ltxm/src/ltxm_uvmap.cpp`(창 구성)와 `ltxm_grid.cpp`(오버레이·조작, 약 1,200 줄).

| 창 | 기능 |
|---|---|
| Texture Mapping Editor | lbx-gui 고급 이미지 뷰어(확대·픽셀 격자·체커 배경), 격자 오버레이, 격자 선택·이동, 8방향 크기 조절, 선 끌기, 길게 눌러 선 편집 모드 전환, L 화살표로 축 방향 표시 |
| Texture Mapping Tool | 격자 추가·삭제·이름, Physical Dimensions, Rotate Physical Axis(옛 `axis`), x/y 뒤집기 버튼(선 배열과 태그 배열을 함께 뒤집음), 구간 수(바꾸면 선을 재분포), 선 번호 선택 + 태그 텍스트, JSON 보기·직접 편집·적용 |

새 형식으로 가면서 걸리는 점:

1. **선 순서 = 축 방향**이고 선끼리 지나칠 수 있다. 순서가 뒤집히는 순간 어느 쪽이 정방향인지 판별할 수 없어, 처음
   만들 때의 방향만 믿는다.
2. 선을 하나씩 넣고 빼는 조작이 없다. 구간 수를 바꾸면 전체를 재분포한다. 가드 키(-1099) 같은 선을 중간에 넣기 어렵다.
3. 태그가 선마다 자유 텍스트라 성격(배치 값·디자인·조인트)이 섞인다.
4. 되돌리기가 없다.
5. 데이터 조작과 ImGui 그리기가 한 함수에 섞여 있다(설계안 §15-6).

기존 격자 편집 화면은 그대로 둔다. 옛 소비자가 계속 `grids` 를 쓰므로 그 편집 수단이 있어야 한다. 래티스 편집은 새
모드로 따로 만든다.

## 3. 래티스 형식 v1

### 3-1. 예

```json5
"lattices": {
  "dpgl_basic": {
    "version": 1,
    "edge": "hard",                          // 선택: 키 경계 샘플링(없으면 쓰는 쪽 기본값)
    "lon": {
      "axis": "-x",                          // 이 축의 + 는 텍스처 x 가 줄어드는 쪽(차에서 멀어지는 쪽)
      "px":  [8,      16,    24,    32,     40,    48,    56,       64,    72,      88],
      "seg": [ "line_w", null,   1, "line_w", null,   1, "line_w",  null,  null   ],
      "handles": [
        { "tag": "safe",   "px": 8  },
        { "tag": "warn",   "px": 32 },
        { "tag": "danger", "px": 56 },
        { "tag": "start",  "px": 72 },
        { "tag": "axle",   "px": 88 }
      ]
    },
    "lat": {
      "axis": "+y",
      "px":  [484,   488,   496,   504],
      "seg": [   null,  null, "line_w" ],        // 투명 · 발 나머지 · 선 두께
      "handles": [
        { "tag": "inner", "px": 484 },
        { "tag": "foot",  "px": 488 },
        { "tag": "side",  "px": 504 }
      ]
    }
  },

  // 9-slice 버튼: 손잡이 없음 → 각 축의 양끝이 기본 손잡이(start/end)
  "btn_wide": {
    "version": 1,
    "lon": { "axis": "+x", "px": [0, 12, 108, 120], "seg": [1, null, 1] },
    "lat": { "axis": "+y", "px": [0, 12, 36, 48],   "seg": [1, null, 1] }
  },

  // 그림자 아웃셋이 있는 패널: 손잡이(맞춤선)가 구간 경계와 다른 자리에 있음
  "panel_shadow": {
    "version": 1,
    "lon": { "axis": "+x", "px": [0, 24, 216, 240], "seg": [1, null, 1],
             "handles": [ { "tag": "fit.l", "px": 16 }, { "tag": "fit.r", "px": 224 } ] },
    "lat": { "axis": "+y", "px": [0, 24, 104, 128], "seg": [1, null, 1],
             "handles": [ { "tag": "fit.t", "px": 16 }, { "tag": "fit.b", "px": 112 } ] }
  }
}
```

`panel_shadow` 에서 `fit.l` 은 고정 구간 0~24 안(16)에 있다. 그래서 0~16 의 그림자는 대상 사각형 밖으로 나가고,
16~24 의 모서리는 안쪽에 남으며, 둘 다 모양을 유지한다. 옛 9-slice 의 `b`·`f` 두 종류 태그가 하던 일을 구간 성질과
손잡이 위치만으로 나타낸다.

DPGL 의 승용차 거리(start 0, danger 500, warn 1000, safe 3000 mm)와 `fix` 구간의 mm 축척(12.5 mm/px)은 래티스에 없다.
이 값들은 **기본 연결**로 둔다. 연결 층의 가장 아래(배포 자산의 가이드 정의 파일)가 그 래티스의 기본 배치를 갖고, 차종
층이 그 위를 덮는다(설계안 §17-7 ②).

```json5
// assets/guides/rear_dynamic.json — 기본 연결(가장 아래 층)
{ "glyph": "car.png#dpgl_basic", "attach": "symmetric", "unit": "mm",
  "scale": { "lon": 12.5, "lat": 12.5 },     // fix 구간: 원천 px 당 목표 단위
  "sizes": { "line_w": 100 },                // 크기 변수: 이 이름이 붙은 구간 전부의 목표 길이
  "lon": { "start": "rear_bumper", "danger": 500, "warn": 1000, "safe": 3000, "axle": "axle.fixed" },
  "lat": { "side": "side", "foot": "side + 500", "inner": "center" } }
```

### 3-2. 필드

| 필드 | 형식 | 뜻 |
|---|---|---|
| `version` | 정수 | 형식 판. 1 |
| `edge` | `"hard"`·`"soft"`, 선택 | 키 경계 샘플링(설계안 §16). 없으면 쓰는 쪽 기본값(SWEEP 은 자동 가드 hard, RECT·BODY 는 soft) |
| `lon`, `lat` | 객체 | 축. 이름은 길이 방향·폭 방향이지만 RECT(UI 그림)에서는 가로·세로로 읽는다 |
| `axis` | `"+x"`·`"-x"`·`"+y"`·`"-y"` | 텍스처 축과 이 축의 + 방향 |
| `px` | 실수 배열(≥ 2) | 구간 경계, 픽셀 오름차순. 같은 값 허용(길이 0 구간) |
| `seg` | 배열(`px` 길이 − 1) | 구간마다 null·숫자·문자열 중 하나. 아래 표 |
| `handles` | 객체 배열, 선택 | `tag`(손잡이끼리 래티스 전체에서 유일), `px`(그 축의 첫 선 ~ 끝 선 사이) |

`seg` 값:

| 값 | 성질 | 목표 길이 |
|---|---|---|
| null | 늘림(`str`) | 이웃 손잡이 사이에서 남는 길이를 원천 길이 비율로 나눠 가짐 |
| 숫자 m | 고정(`fix`), 배율 | 원천 길이 × k × m. 1 이 보통의 고정 |
| 문자열 이름 | 고정(`fix`), 크기 변수 | 연결이 준 그 변수의 값. 값이 없으면 원천 길이 × k |

- 이름을 붙이는 순간 그 구간은 고정이다. 고정은 길이를 정해 두는 것이고, 숫자는 그 길이를 k 에 대한 배율로, 이름은
  연결이 주는 값으로 정할 뿐이다. 값이 없으면 늘림이다.
- 크기 변수는 여러 구간·두 축이 같은 이름을 쓸 수 있다. 선폭처럼 디자인 전체에 걸친 크기를 한 곳에서 바꾸는 장치다
  (예: `line_w` 를 100 mm 에서 200 mm 로 바꾸면 세 발과 사이드 라인 두께가 함께 바뀐다). 값은 래티스가 아니라 연결이 준다.
- `"fix"`·`"str"`·`"rep"` 는 예약어다. 크기 변수 이름으로 쓸 수 없고, 초안 1 형식으로 쓴 파일을 읽을 때 `"fix"` 는 1,
  `"str"` 은 null 로 읽는다. `"rep"`(반복)는 v1 에서 자리만 둔다(읽으면 늘림으로 처리하고 진단). 쓰임새 후보는 타이어
  자국 무늬처럼 경로를 따라 같은 무늬가 이어지는 띠 — 반복 경계에서 정점을 나눠 UV 를 다시 시작하면 된다(설계안 §9).
- 본문의 `fix`·`str` 은 이 성질의 이름이다. 저장 값은 위 표를 따른다.

물리 단위·축척·기본 배치 값·크기 변수 값은 래티스에 두지 않는다. 같은 그림을 어떤 단위로 어떻게 붙일지는 연결이 정한다.

래티스가 차지하는 영역은 두 축의 첫 선 ~ 끝 선이다. 사각형을 따로 적지 않는다.

### 3-3. 검사 규칙

1. `px` 는 오름차순(같은 값 허용), 2개 이상.
2. `seg` 길이 = `px` 길이 − 1, 값은 null·양수·예약어가 아닌 문자열.
3. `lon.axis` 와 `lat.axis` 는 서로 다른 텍스처 축.
4. 손잡이 `px` 는 그 축의 범위 안, 손잡이 `tag` 는 래티스 전체에서 유일(축이 달라도 같은 이름 금지 — 연결에서 이름
   하나로 찾게). 태그가 붙는 것은 손잡이뿐이다. 경계선에는 태그가 없고, 손잡이가 없는 축의 기본 손잡이(첫 선·끝 선)도
   태그 없이 형상으로 정해진다.
5. 모르는 필드는 보존한다(읽고 다시 쓸 때 잃지 않는다).

검사 실패는 오류 목록으로 돌려주고, 편집기는 진단 창에 띄운다. 소비 쪽은 그 래티스를 쓰지 않는다.

## 4. 1차원 풀이

축마다 따로 푼다. 편집기 미리보기와 소비 쪽이 같은 함수를 쓴다.

**입력**: 축(선·구간·손잡이·방향), 손잡이별 목표 값(연결 층을 합친 값, 없으면 목표 없음), `fix` 축척 k(원천 px 당
목표 단위, 연결이 줌, 없으면 1), 크기 변수 값(연결이 줌).
**출력**: 모든 선과 손잡이의 목표 위치, 진단 목록.

1. 원천 좌표 t 를 정한다. `+` 축이면 t = px − px₀, `-` 축이면 t = pxₙ − px. 이후 계산은 t 로 한다.
2. 목표 값이 있는 손잡이를 t 순서로 모은다. 하나도 없으면 첫 선·끝 선을 기본 손잡이(태그 없음)로 두고, 그 목표는
   쓰는 쪽이 준다(RECT 의 사각형 두 변). 목표가 있는 손잡이가 하나뿐이면 늘릴 곳이 없으므로 그 손잡이를 기준으로
   전체를 축척 k 로 붙인다(위치만 옮김).
3. 목표 값이 t 순서로 모두 증가하면 그대로, 모두 감소하면 뒤집어 놓는다(오른쪽 가이드처럼 반대로 붙이는 경우).
   섞여 있으면 진단 `order` 를 내고 어긋난 손잡이의 목표를 쓰지 않는다.
4. 이웃 손잡이 A·B 사이(손잡이가 구간 안에 있으면 그 자리에서 구간을 나눈다):
   - F = Σ(`fix` 목표 길이), S = Σ(`str` 원천 길이), L = |목표 B − 목표 A|. `fix` 목표 길이는 §3-2 표대로 원천 길이 × k × 배율
     이거나 크기 변수 값이다. 손잡이가 크기 변수 구간 안에 있어 구간이 나뉘면 조각마다 원천 길이 비율로 값을 나눈다.
   - S > 0 이고 L ≥ F: `str` 구간이 (L − F) 를 원천 길이 비율로 나눠 갖는다.
   - L < F: `fix` 를 L/F 로 줄이고 `str` 은 0, 진단 `compressed`.
   - S = 0 이고 L > F: `fix` 를 늘리지 않고 진단 `cannot_fit`(B 쪽에 틈이 남는다).
5. 가장 바깥 손잡이의 바깥은 `seg` 와 상관없이 원천 길이 × k 로 이어 붙인다(아웃셋).
6. 손잡이가 `fix` 구간 안에 있으면 그 구간은 손잡이와의 오프셋을 유지한 채 함께 움직인다. 4 의 분할로 저절로 그렇게
   된다(양쪽 조각이 모두 `fix`). 길이 리그의 축이 펜더 고정 구간 가운데에 있지 않은 경우(zone_f ≠ zone_b)가 이것이다.

**확인용 예** — 설계안 §17-5 의 노랑 구간 A/B 두 디자인(단위 mm, 목표: warn 3000, danger 1000):

| 선 px | A (`fix` `str` `fix`) | B (`fix` `fix` `str`) |
|---|---|---|
| 32 (warn) | -3000 | -3000 |
| 40 | -2900 | -2900 |
| 48 | -1100 | -2800 |
| 56 (danger) | -1000 | -1000 |

`fix` 축척 12.5 mm/px 기준. 기본값(warn 1000, danger 500)에서 A 는 지금 격자 값(-1000, -900, -600, -500)과 같고, B 는
노랑 끝이 -800 이다(몸통 8 px = 100 mm 를 고정하므로). 400 mm 짧은 사이드 라인을 원하면 그림에서 몸통을 24 px 로 그린다.
위 값은 ltxm `--selftest` 가 확인한다.

크기 변수 예: A 디자인의 세 발(8~16, 32~40, 56~64)에 `line_w` 를 붙이고 값을 200 mm 로 주면(트럭 목표 safe 10000,
warn 3000, danger 1000) 각 발 안쪽 선이 9800·2800·800 이 된다. 값을 주지 않으면 원천 길이 × k(100 mm)로 돌아가
9900·2900·900 이다. 이것도 `--selftest` 가 확인한다.

## 5. 옛 격자와의 관계

### 5-1. 저장

- 같은 PNG `mesh` 청크 JSON 에 `lattices` 키를 추가한다. `grids` 는 그대로 둔다.
- 옛 소비자는 `grids` 만 읽으므로 영향이 없다. 래티스를 쓰는 소비자는 `lattices` 를 먼저 찾고, 없으면 옛 `grids` 를
  변환해 쓴다(5-2 와 같은 변환기).
- ltxm 은 읽은 JSON 전체를 보존해 다시 쓴다. 모르는 키를 잃지 않는다.
- 래티스와 격자를 자동으로 동기화하지 않는다. 진실이 둘이 되는 것을 막기 위해, 래티스는 편집기에서 명시적으로 만든
  것만 저장된다.

### 5-2. 변환(격자 → 래티스)

편집기의 "격자에서 래티스 만들기" 조작으로만 일어난다. 원본 격자는 고치지 않는다.

| 옛 격자 | 래티스 |
|---|---|
| 선 배열(거꾸로 적힌 것 포함) | 오름차순 정렬. 거꾸로였으면 그 축의 `axis` 를 `-` 로 |
| `axis: 1` | `lon.axis` 를 y 계열로 |
| 9-slice `b` | 그 선 바깥 구간을 `fix` |
| 9-slice `f` | 같은 자리의 손잡이(`fit.l` 등) |
| 9-slice `x`(가운데 비움) | 칸 수동 지정(v1 범위 밖 — 변환 때 경고) |
| DPGL 숫자 태그 | 사용자가 고른 "배치 대상" 태그만 손잡이(이름 = 태그 문자열). 명목 값은 래티스가 아니라 기본 연결 파일로 내보낸다(§3-1 끝). 나머지 선은 경계만 |
| DPGL `seg` | 배치 대상 손잡이에 맞닿은 짧은 구간 `fix`, 나머지 `str` 을 **기본 제안**으로 채우고 사용자가 확인·수정 |
| DPGL 손 가드(`-1099` 처럼 1 텍셀 안팎 구간) | 지움(자동 가드가 대신) |
| DPGL `center`(반사) | 손잡이 `inner`. 반사는 쓰는 쪽의 대칭 붙이기 |
| `axle` | 손잡이 `axle`(목표는 쓰는 쪽 조인트) |

설계안 §4-3 의 "가까운 핀" 추론은 이 기본 제안을 만들 때만 쓴다. 고정 구간이 핀 간격의 절반보다 길면 진단으로 알린다.

## 6. 편집기 UI

지금의 선 중심 격자 편집기(Grid 모드)는 그대로 두고, 구간 중심 편집기를 Lattice 모드로 새로 만든다.

### 6-1. 작업 흐름

1. **영역 잡기.** 텍스처 위에 래티스가 차지할 사각형을 끌어 잡는다. 이 사각형의 네 변이 두 축의 첫 선·끝 선이 된다.
2. **좌표계 정하기.** 사각형 네 모서리의 원 중 하나를 클릭하면 그 모서리가 원점이 된다(§6-4).
3. **나누기.** 세 가지 수단을 섞어 쓴다.
   - 처음 N등분(만들기 틀, §6-7). 그 뒤로는 **선택한 구간만** N등분한다. 전체를 다시 나누면 이미 칠한 성질과 손잡이가
     깨지기 때문이다.
   - 선 긋기(선 도구).
   - 그림 내용으로 제안 받기(§6-5).
4. **구간 성질 칠하기.** 자 띠를 칠해 `fix`·`str` 를 정한다. 자 띠 바탕의 "늘림 안전도"(§6-5)를 참고한다.
5. **바로 늘려 보기.** Alt + 끌기로 그 자리에서 늘려 본다(§6-9). 놓으면 원래대로 돌아간다.
6. **손잡이 놓기.** 손잡이 도구로 직선을 놓고 태그를 붙인다. 태그는 사전에서 자동 완성한다(§6-8).
7. **변종 만들기·최종 확인.** 필요하면 복제해 A/B 디자인을 만들고(§6-10), 미리보기 창에서 목표 값과 진단을 확인한다.

### 6-3. 표시 규칙

| 요소 | 그림 |
|---|---|
| 구간 경계선 | 래티스 전체를 가로지르는 가는 회색 선 |
| 제안선(§6-5) | 자 띠와 이미지에 걸친 점선. 받으면 경계선이 된다 |
| 점선 그리는 법 | 흰·검 반복 텍스처(8×1, 반복·최근접)를 붙인 사각형 하나. 보이는 부분(클립 사각형)만 잘라 붙인다. 조각마다 선을 그리면 확대할수록 정점이 늘어 ES 백엔드의 16비트 인덱스(VtxOffset 없음)를 넘기고 화면이 깨진다(2026-10-29 실측). 흰 칸은 선 색, 검은 칸은 검정이라 어느 바탕에서나 보인다 |
| 손잡이 | 굵은 색 선(래티스 전체를 가로지름) + 자 띠 위 태그 칩 |
| `fix` 구간 | 자 띠에서 채운 막대(주황) |
| `str` 구간 | 자 띠에서 양방향 화살표 무늬(파랑) |
| 배율 고정 구간 | 주황 막대에 `x2` 처럼 배율 표시 |
| 크기 변수 구간 | 자 띠에서 보라 막대에 변수 이름 |
| 늘림 안전도(§6-5) | 자 띠 바탕의 옅은 색: 늘려도 티가 안 나는 구간은 초록, 늘리면 일그러지는 구간은 붉은 기 |
| 길이 0 구간 | 자 띠에서 겹친 두 선을 한 선으로 그리고 작은 표시 |
| 원점·축 방향 | 원점 모서리의 노란 채운 원(나머지 세 모서리는 회색 원), 네 원 모두 검은 테를 둘러 어느 바탕에서나 보이고 마우스를 올리면 커진다. 두 번 누르면 lon·lat 도 바꾼다(§6-4). 원점에서 뻗은 화살표 두 개. 이름은 대상 좌표축으로 단다(`+X lon`·`+Y lat`) — 래티스가 아는 것은 "텍스처의 어느 방향이 대상의 +X·+Y 인가" 하나이므로 그것을 그대로 보여 준다. 래티스는 원점에서 + 쪽으로만 펼쳐지므로 -X·-Y 는 그리지 않는다 |
| 변종 차이(§6-10) | 다른 변종과 `seg` 가 다른 구간을 자 띠에서 빗금으로 강조 |
| 진단 | 해당 구간을 붉은 테두리, Preview 창과 Lattice 창에 목록 |

손잡이는 점이 아니라 직선으로 그린다. 분리형 래티스에서 손잡이는 그 행·열 전체를 잡기 때문이다. 교차점이 필요한 경우
(설계안 §6-5 레벨 2)는 v1 범위 밖이다.

### 6-4. 도구와 조작

| 도구(키) | 조작 | 결과 |
|---|---|---|
| 선택(V) | 빈 곳 끌기(래티스가 없을 때) | 새 래티스 영역 잡기(만들기 틀 선택이 이어서 열림) |
| 선택(V) | 래티스 안 끌기 / 바깥 변 끌기 | 래티스 전체 이동 / 바깥 선 이동(안쪽 선은 그대로) |
| 선택(V) | 선 끌기 | 그 선 이동. 이웃 선을 넘지 못한다(같은 자리까지는 가능). 픽셀 단위로 맞춤(Shift 로 해제) |
| 선택(V) | 자 띠의 구간 클릭(Ctrl 로 여럿) | 구간 선택. Lattice 창의 "선택 구간 N등분" 이 그 구간에만 적용되고, 새 구간은 원래 성질을 물려받음 |
| 선(L) | 자 띠 클릭 / 영역 안에서 끌기 | 그 축에 경계선 추가 / 끄는 방향이 선의 방향(가로로 끌면 가로선, 세로로 끌면 세로선), 자리는 누른 점, 놓을 때 추가. 나뉜 두 구간은 원래 성질을 물려받음 |
| 선(L) | 선 선택 후 Del | 경계선 삭제. 합쳐진 구간은 양쪽이 같으면 그대로, 다르면 `str`(알림 표시) |
| 공통 | [제안 받기] / 제안선 클릭 | 제안선 모두 받기 / 하나만 받기(§6-5) |
| 구간 붓(B) | 자 띠 클릭 / 끌기 | `fix` ↔ `str` 전환 / 끈 범위를 처음 고른 성질로 칠함(9-patch 칠하기) |
| 구간 붓(B) | Shift + 자 띠 클릭 | 늘림 안전도대로 그 축 전체를 한 번에 칠함(안전 = `str`, 아니면 `fix`) |
| 손잡이(H) | 자 띠·경계선 클릭 / 영역 안에서 끌기 | 그 축에 손잡이 추가 / 선 도구와 같이 끄는 방향으로 축을 정함. 가까운 경계선에 맞춤(Shift 로 해제), 태그 입력란이 자동 완성과 함께 열림 |
| 손잡이(H) | 손잡이 끌기 / Del | 이동 / 삭제 |
| 공통 | 모서리 원 클릭 / 두 번 클릭 | 그 모서리를 원점으로(두 축의 + 방향이 정해짐). 선·구간·손잡이는 그대로 / 거기에 더해 lon·lat 교환(90° 돌리기). 교환은 축마다 부호를 함께 옮기므로 원점 모서리는 그대로다. 모서리 넷 × 교환 둘 = 8 방향 |
| 공통 | 화살표 클릭 | lon·lat 교환(어느 텍스처 축이 lon 인지 바뀜) |
| 공통 | Alt + 바깥 변 끌기 / Alt + 손잡이 끌기 | 그 자리에서 늘려 보기(§6-9). 놓으면 원래대로 |
| 공통 | Ctrl+Z / Ctrl+Y | 되돌리기 / 다시 하기 |

숫자 표(Lattice 창)에서 px·구간 성질·태그를 직접 고칠 수 있다. 표와 그림은 같은 데이터를 본다.

구간 성질 칸은 글자 입력란이다. 규칙은 JSON 의 `seg` 와 같다: 비우거나 `str` 이면 늘림, `fix` 면 배율 1 고정,
숫자면 그 배율로 고정, 이름이면 크기 변수로 고정. 칸 바탕색은 자 띠와 같다(파랑·주황·보라).
- 배율은 `2`·`x 2`·`*2` 로 넣고 `x 2` 로 보인다. 변수 이름이 될 수 없는 꼴(띄어 쓰기)로 적어 변수와 구별한다.
  `x2` 는 이름이므로 크기 변수다.
- 변수 이름은 글자·`_` 로 시작하고 글자·숫자·`_` 만 쓴다. 그 밖의 글자는 받지 않고 까닭을 알린다.
- JSON 에서는 여전히 숫자는 숫자, 이름은 문자열이다. `x 2` 는 화면 표기일 뿐이다.
- 읽을 때 var 의 문자열 형 셋(5 글자 이하 SSTR·USTR·CSTR)을 모두 문자열로 본다. 처음에는 USTR 만 보아 `w`·`width`
  같은 짧은 이름과 옛 예약어 `fix`·`str` 이 숫자로 읽혔다(2026-10-29 수정, 자체 시험에 넣음).

자 띠에서 구간을 고르면 Lattice 창에 "N selected segments" 줄이 나타나 같은 글자 규칙으로 한꺼번에 넣고 N등분한다.

같은 성질 구간 합치기(Merge equal segments): 이웃한 늘림-늘림, 같은 배율의 고정-고정 사이 선을 지운다. 위치 풀이는
같다. 크기 변수 구간은 구간마다 변수 값 전체를 가지므로 남긴다. 제안선 받기 뒤 생기는 1~2 px 조각을 줄이는 데 쓴다.
Key edges 가 hard 면 선마다 샘플링을 반 텍셀 당기므로(리그 설계안 §16), 그림 내용이 바뀌는 자리의 선(DPGL 폭 키 같은
내용 경계선)은 남긴다.

핀은 경계선 위에만 있지 않다. 그림자가 있는 버튼의 `fit.*` 처럼 구간 가운데에 놓이는 핀은 축 표에서 그 구간의 두
경계선 사이에 분홍 "pin" 줄로 자리 순서대로 끼운다(자리 입력·태그 칩). 경계선 위의 핀은 그 선 줄의 pins 칸에 칩으로
보인다. 칩을 누르면 고르고, 오른쪽 단추로 이름 바꾸기·지우기를 한다. 따로 두던 핀 목록은 없앴다.

Lattice 창에는 늘 쓰는 것만 둔다. 만들기 틀 설정은 New 를 누른 뒤 그리기를 기다리는 동안만, 제안 문턱·버튼은
Suggestions 를 켰을 때만, 선택 구간 줄은 고른 구간이 있을 때만 보인다. 뷰 조작 요령은 (?) 풍선 도움말로 옮겼다.

### 6-5. 그림 내용으로 분할선·성질 제안

래티스 영역이 정해지면 축마다 텍스처를 한 줄씩 비교해, 디자이너가 손으로 선을 긋는 일을 "제안 받기"로 줄인다.

- **이웃 줄 차이.** lon 축이 x 라면 영역 안의 이웃한 두 열 c, c+1 에 대해 D(c) = 영역 행 전체에서 두 픽셀 차이의
  최댓값(채널별, 미리 곱한 알파로 비교해 투명 픽셀의 숨은 색은 무시). lat 축은 행끼리 같은 방식.
- **분할선 제안.** D(c) 가 문턱(기본 8/255)을 넘는 자리 c+1 이 내용 경계다. 차이가 여러 열 이어지면(안티앨리어스된
  가장자리, 그라데이션) 그 이어진 구간의 양 끝을 제안하고, 그 사이는 따로 한 구간이 되게 한다.
- **늘림 안전도.** 구간 [a, b) 안의 D 가 모두 문턱 이하면 모든 열이 같아 늘려도 티가 나지 않는다(`str` 후보). 하나라도
  넘으면 늘리면 일그러진다(`fix` 후보). 자 띠 바탕색으로 늘 보여 주고, Shift + 붓 클릭으로 그대로 칠할 수 있다.
- **예.** car.png 의 DPGL 영역이면 길이 축에서 색·발 경계(16·24·32·40·48·56·64·72)가 제안되고, 색 몸통 구간이
  안전(초록), 발 구간이 불안전으로 표시된다. 9-slice 버튼은 모서리 둥근 부분이 불안전, 가운데가 안전으로 나와 제안을
  받고 Shift + 칠하기 한 번으로 끝난다.
- 판정은 단순한 픽셀 비교라 영역이나 선을 바꿀 때마다 다시 계산한다(512×512 아틀라스의 한 영역이면 1 ms 안팎).
  텍스처 픽셀은 ltxm 이 이미 CPU 에 갖고 있다(이미지 뷰어의 픽셀 값 표시가 쓰는 것).

### 6-6. 좌표계 정하기

- 사각형 네 모서리에 작은 원을 두고, 클릭한 모서리가 원점이 된다. 원점에서 lon·lat 두 화살표가 뻗는다. 화살표를 클릭하면
  lon·lat 가 서로 바뀐다.
- 8가지 조합을 목록에서 고르는 것보다 그림 위에서 바로 읽힌다. 저장은 축마다 `axis` 값 하나(`"-x"` 등)이고, 바꿔도
  선·구간·손잡이는 그대로다(선은 늘 픽셀 오름차순).

### 6-7. 만들기 틀

영역을 잡으면 틀을 고른다. 여백이나 개수만 넣으면 구간이 만들어진다(설계안 §15-4 의 간편함 유지).

| 틀 | 입력 | 결과 |
|---|---|---|
| N등분 | 축마다 개수 | 축마다 같은 간격의 선, 전부 `str`(지금 격자 편집기의 "몇 개로 나누기") |
| 9-slice | 좌·상·우·하 여백 | 축마다 선 4개, `fix` `str` `fix` |
| 9-slice + 아웃셋 | 위 + 그림자 폭 | 위 + 손잡이 `fit.*` 를 그림자 안쪽 끝에 |
| 내용에서 | — | §6-5 제안을 모두 받고 늘림 안전도대로 칠한 상태로 시작 |
| 격자에서 | 옛 격자 선택 + 배치 대상 태그 선택 | §5-2 변환, 결과를 확인 대화상자에서 고친 뒤 확정 |
| 복제 | 지금 래티스 | 같은 선·구간·손잡이, 이름만 새로(변종 만들기, §6-10) |

### 6-8. 손잡이 태그 사전

- 태그를 자유 입력으로만 받으면 그림마다 `danger`·`Danger`·`dng` 처럼 갈라져, 연결 UI 에서 같은 뜻을 찾기 어려워진다.
- 태그 입력란은 사전 파일에서 자동 완성한다. 사전 항목은 태그, 쓰는 축 힌트(lon·lat·어느 쪽이든), 짧은 설명(영어 원문,
  번역은 저장 체계 통일 설계의 다국어 방식)이다.
- 사전에 없는 이름을 넣으면 그대로 쓰되 "사전에 추가" 단추를 보여 준다.
- 사전 자리: 처음엔 ltxm 의 config 폴더(`config/ltxm-tags.json`). svmdemo 연결 UI(E3)가 생기면 같은 설명을 보여 줄 수
  있게 배포 자산 쪽으로 옮긴다.

```json5
{ "tags": [
  { "tag": "start",  "axis": "lon", "desc": "Where the guide begins (usually the rear bumper)" },
  { "tag": "danger", "axis": "lon", "desc": "Far end of the danger zone" },
  { "tag": "warn",   "axis": "lon", "desc": "Far end of the warning zone" },
  { "tag": "safe",   "axis": "lon", "desc": "Far end of the guide" },
  { "tag": "side",   "axis": "lat", "desc": "Vehicle side line" },
  { "tag": "fit.l",  "axis": "any", "desc": "Left edge of the target rectangle" } ] }
```

### 6-9. 미리보기

디자인만 보고는 결과를 알 수 없다(설계안 §15-8). 두 가지를 둔다.

**뷰 안에서 바로 늘려 보기(빠른 확인).**
- Alt + 바깥 변 끌기: 그 축의 전체 목표 길이를 임시로 바꾼다. 손잡이가 있으면 바깥 손잡이의 목표가 바뀌는 것으로 본다.
- Alt + 손잡이 끌기: 그 손잡이의 목표만 임시로 옮긴다(나머지 손잡이는 원천 위치 그대로).
- 풀이 결과를 그 자리에 그리고(원본은 옅게 깔림), 진단이 나오면 구간을 붉게 표시한다. 놓으면 원래대로 돌아가며
  디자인 데이터는 바뀌지 않는다.
- 구간 하나를 칠하고 바로 끌어 보는 짧은 사이클이 목적이다. 같은 풀이 함수(lbx-geo `lbx_lattice`)를 쓴다.

**Preview 창(정식 확인).**
- 손잡이마다 목표 값(처음엔 고른 프리셋의 값). 손잡이가 없는 래티스는 축마다 전체 길이.
- 축마다 `fix` 축척 k.
- 래티스에 쓰인 크기 변수를 모두 나열한다(Size variables). 연결하지 않으면 원천 길이 × k 로 푼다. Sel 은 그 변수를
  쓰는 구간을 자 띠에서 고른다.
- 값은 모두 끌어서 바꾼다(DragFloat, 두 번 누르면 입력). 바꾸지 않은 값은 흐리게 원천 값을 따라가고, 바꾸면 그 값에
  묶이며 옆의 `x` 로 풀면 원천 값으로 돌아간다.
- 그리기는 미리보기 전용 텍스처 사본을 쓴다. 사본은 LINEAR 이고, 알파 0 텍셀의 RGB 를 이웃 불투명 텍셀 색으로
  채운다(알파 번짐 2 텍셀). 원본은 투명 칸이 검정이라 LINEAR 로 섞으면 도형 겉에 회색 테두리가 생긴다.
- 사본만으로는 확대 때의 NEAREST 를 막지 못했다. 원인은 lbx-gui 의 ImGui GL 백엔드다. ES2 빌드(`IMGUI_IMPL_OPENGL_ES2`)는
  샘플러 객체가 없어 `DrawCallback_SetSamplerNearest` 를 "이후 그리는 텍스처마다 `glTexParameteri`" 로 흉내 내는데,
  Image Viewer 가 그린 뒤 보내는 `ResetRenderState` 로도 그 흉내를 끄지 않았다. 그래서 뷰어를 확대하면 그 뒤에 그리는
  모든 창의 텍스처(미리보기 사본 포함)가 NEAREST 로 바뀌었다. hard 는 반 텍셀 당김이라 차이가 거의 없어 soft 에서만
  드러났다. lbx-gui `imgui_impl_opengl3.cpp` 에서 `ResetRenderState` 와 프레임 시작 때 흉내를 끄도록 고쳤다
  (2026-10-29, ltxm 에는 lbx-gui 배포 후 반영).
- `edge` 를 반영한다. hard 면 칸마다 UV 를 경계에서 반 텍셀 안으로 당겨 이웃 칸 텍셀을 섞지 않는다(lbsvm
  `TLBBand::GuardKeyEdges` 와 같은 결과, 리그 설계안 §16). 값이 없으면 RECT·BODY 기본값인 soft 로 그린다.
  뷰 안 Alt + 끌기 미리보기도 같다.
- 보기 좌표계(View): 대상 시스템의 좌표계를 고른다. Texture(그린 그대로), Screen(+X 오른쪽, +Y 아래 — UI 그림),
  ISO 8855 위에서 본 그림(+X 위, +Y 왼쪽 — DPGL). lon 은 늘 대상 X, lat 은 늘 대상 Y 이고, 그림이 대상 좌표계에서
  어느 쪽을 향할지는 래티스 축(원점 모서리·Swap)으로 맞춘다. 이 창은 그렇게 맞춘 결과가 원하는 방향으로 나오는지
  확인하는 곳이다. Texture 에서는 축 방향을 뒤집어도 그림이 그대로이므로 방향 확인은 Screen·ISO 8855 로 한다.
- 결과를 곧은 띠(또는 사각형)로 그린다. 칸마다 원천 UV 를 목표 사각형에 그대로 붙이므로 ImGui 그리기 목록의
  `AddImage` 로 충분하고, lbsvm-core 가 필요 없다.
- 진단(`compressed`·`cannot_fit`·`order`)을 구간 위와 목록에 표시.
- 래티스 겹쳐 그리기(항상 / 마우스를 올렸을 때만 / 끔, 기본은 마우스를 올렸을 때만 — 핀을 옮겨 본 뒤 마우스를 빼면 결과만
  보인다. 올려 둔 채 Space 를 누르고 있으면 잠깐 숨긴다): 늘어난 결과 위에 영역 테두리, 경계선, 바깥쪽 구간 띠(편집 화면 자 띠와 같은
  색 — 늘림 파랑·고정 주황·크기 변수 보라), 핀 선과 태그 칩. 띠와 태그는 영역 중심에서 바깥쪽으로 붙여 보기 좌표계가
  축을 어느 쪽으로 돌려도 영역 밖에 놓인다(lon 띠는 lat 최소 쪽 변, lat 띠는 lon 최소 쪽 변). 핀 태그에는 이름과 목표 값을 함께 쓴다.
  진단(`compressed`·`cannot_fit`)이 난 첫 구간은 칸과 띠를 붉게 칠한다.
- 원천 크기(Source size, 기본 켬): 늘리기 전 크기(원천 px × k)를 첫 선 자리에서 점선 사각형으로 겹쳐 그린다. 미리보기는
  창에 맞춰 축척을 다시 잡으므로, 이것이 없으면 두 배로 늘려도 화면에서는 비슷해 보인다.
- 캔버스에서 직접 끌기: 핀 선을 끌면 그 핀의 목표가 바뀐다. 핀이 없는 축은 끝 선(마지막 선)을 끌어 길이를 바꾼다.
  끄는 동안에는 누를 때의 화면 축척을 유지하고(매 프레임 창에 맞추면 변이 마우스 밑에서 미끄러진다) 놓으면 다시
  맞춘다. 끄는 동안 커서 옆에 값(핀 값 또는 가로 × 세로)을 보인다.
- 핀을 묶는 방식: 핀 하나를 바꾸기 시작하면(값 끌기·캔버스 끌기 모두) 같은 축의 나머지 핀을 지금 화면에 놓인 자리에
  함께 묶는다. 풀이 규칙(§4 2 항)은 묶인 핀이 하나뿐이면 옮기기만 하므로, 그대로 두면 핀 하나를 끌어도 그림이 늘어나지
  않는다(써 보며 확인). 미리보기 값을 넣는 방식일 뿐 형식·풀이는 그대로다. 묶지 않은 핀의 값은 원천 위치가 아니라 지금
  놓인 자리를 보여 준다. 핀이 하나뿐인 축은 늘릴 곳이 없다고 알린다.
- 마우스를 올린 구간: 미리보기 칸에 노랑 테, 풍선 도움말(구간 번호·성질·원천 px → 목표 길이). 편집 화면 자 띠와 영역,
  축 표의 같은 줄도 함께 강조한다.
- 미리보기 값은 편집기 세션 값이다. 래티스에 저장하지 않는다(디자인과 배치를 섞지 않는다). 자주 쓰는 값은
  "미리보기 프리셋" 으로 ltxm 의 config 폴더 설정에 둔다(예: 승용차 기본값, 트럭 1/3/10 m). E3 이후에는 기본 연결
  파일이나 차종 연결 파일을 **읽기 전용**으로 열어 그 값으로 미리볼 수 있게 한다.
- 곡선 미리보기(조향 반경으로 휘는 띠)는 2 단계로 미룬다.

### 6-10. 변종 비교

- 같은 픽셀 영역(두 축의 첫 선·끝 선이 같은)을 쓰는 래티스들을 뷰 위쪽에 탭으로 나란히 둔다.
- 탭을 바꾸면 다른 변종과 **`seg` 가 다른 구간**을 자 띠에서 빗금으로 강조하고, 한쪽에만 있는 선은 점선으로 보여 준다.
  "복제 → 한 구간만 바꾸기"로 만든 A/B 디자인의 차이가 한눈에 보인다.
- Preview 창에서 같은 목표 값으로 두 변종을 위아래로 나란히 그려 비교할 수 있다.

### 6-11. 되돌리기

편집 한 번(끌기는 놓을 때 한 번)마다 래티스 var 전체를 복사해 둔다. 래티스는 작아(수백 바이트) 50 단계로도 부담이
없다. 격자 모드에도 같은 장치를 쓸 수 있다.

### 6-12. 그림만 바꾸기(2026-10-30)

PNG 에는 픽셀과 `mesh` 청크(래티스·그리드 JSON)가 함께 들어 있다. 디자인을 다른 편집기에서 고치면 대개 우리 청크가
지워지므로, 래티스·그리드는 두고 그림만 바꾸는 길이 필요하다. 예전에는 두 길이 숨어 있었다.

- Open 이 청크 없는 PNG 를 열 때 이전 데이터를 비우지 않아 래티스가 그대로 남았다. 의도한 쓰임새였지만 안전장치가 없어,
  상관없는 그림을 열어도 래티스가 따라왔다.
- JSON 창(Show JSON → 다른 그림 열기 → Apply Changes)은 버퍼가 4 KB 라 선이 많으면 잘려 적용되지 않았고, 틀린 JSON 을
  적용하면 데이터가 오류 값으로 바뀌었다.

정리한 동작(파일에서 오는 것은 File 메뉴, 클립보드는 Edit 메뉴):

| 동작 | 단축키 | 내용 |
|---|---|---|
| File > Open | Ctrl+O | 청크가 있으면 그 데이터로 연다. 청크가 없고 지금 데이터가 기본 그리드가 아니면 묻는다: 예 = 지금 래티스·그리드 유지(그림만 교체), 아니요 = 새로 시작, 취소 |
| File > Replace Image | Ctrl+Shift+O | 다른 파일의 픽셀만 가져온다. 래티스·그리드와 파일 이름은 그대로 |
| File > Reload Image | Ctrl+R | 지금 파일을 다시 읽어 픽셀만 바꾼다. 외부 편집기가 같은 파일을 덮어써 청크가 지워져도 ltxm 이 데이터를 갖고 있으므로 Save 하면 다시 들어간다 |
| Edit > Paste Image | Ctrl+V | 클립보드 그림을 지금 그림 위에 띄운다(겹쳐 붙이기). 끌기·화살표(Shift = 10 px)로 옮기고 Enter 로 확정, Esc 로 취소한다. 확정하면 straight alpha 끼리 "over" 로 겹쳐 그린다 |
| Edit > Paste Replacing Image | Ctrl+Shift+V | 클립보드 그림으로 그림 전체를 바꾼다(크기가 바뀔 수 있다). 래티스·그리드는 그대로 |
| Edit > Copy Image | Ctrl+C | 지금 그림을 `PNG` 와 `CF_DIBV5` 로 클립보드에 올린다(다른 편집기로 넘기는 반대 방향) |
| Edit > Clear Image | — | 모든 픽셀을 투명하게 한다. 크기·래티스·그리드는 그대로. Delete 는 래티스 선·핀 지우기와 겹치므로 단축키를 두지 않는다 |

클립보드 형식은 알파가 보존되는 순서로 받는다: `PNG`(포토샵·Paint.NET·Krita·브라우저) → `CF_DIBV5` → `CF_DIB`(32 비트인데
알파가 모두 0 이면 불투명).

- 그림만 바꿀 때 크기가 다르면 묻는다: 예 = 래티스·그리드 좌표를 비율대로 옮김(정수 픽셀로 반올림), 아니요 = 픽셀 위치
  그대로, 취소.
- 겹쳐 붙이기가 기본(Ctrl+V)인 까닭: 그림 일부만 고쳐 넘기는 일이 많다. 포토샵류(PhotoCraft 포함)는 레이어를 복사하면
  내용이 있는 범위로 잘라 클립보드에 올리고, 원래 자리는 자기 프로그램 안에만 둔다(2026-10-30 확인: 클립보드에는
  182×102 `PNG`·`CF_DIBV5` 뿐이고 위치 정보가 없다. PhotoCraft 실행 파일에는 "clipboard origin" 문구와 내부 클립보드
  비우기 메뉴가 있다). 그래서 다른 프로그램은 자리를 알 수 없다. ltxm 은 같은 크기면 (0,0) 에, 아니면 화면에 보이는
  캔버스 부분의 가운데(캔버스 안으로 당김)에 놓고 사용자가 옮긴다. 뷰어가 넓으면 뷰어 가운데는 캔버스 밖일 수 있어
  뷰어 가운데를 기준으로 삼지 않는다. 떠 있는 동안은 래티스·그리드 편집을 멈추고, ImGui 키보드 탐색을
  꺼서 Enter·화살표를 빼앗기지 않게 한다.
- 덮어쓰기는 Ctrl+Shift+V 또는 Clear Image 뒤 붙이기다. 같은 크기 그림을 겹쳐 붙이면 교체처럼 보이지만, 고친 그림에서
  지운 부분이 옛 그림에 남으므로 교체는 따로 둔다.
- 되돌리기: Edit 메뉴의 Undo(Ctrl+Z)·Redo(Ctrl+Y)는 래티스 편집과 그림 편집(겹쳐 붙이기, 교체, Replace·Reload, Clear)이
  한 기록을 쓴다. 두 기록은 따로 쌓되 걸음마다 순번을 붙여, Undo 는 더 나중 것을, Redo 는 가장 먼저 되돌린 것을
  다시 한다. 그림 걸음은 픽셀 사본(합계 256 MB 상한, 넘으면 오래된 것부터 버림)이고, 크기를 바꾸며 좌표를 옮긴
  경우에만 그때의 데이터 JSON 도 함께 둔다. Grid 모드에서는 래티스 걸음을 건너뛴다(보이지 않는 것을 되돌리지 않게).
  Open 으로 새 문서를 열면 기록을 비운다. 붙인 조각이 떠 있는 동안 Undo 는 꺼진다(Esc 가 취소).
- Paste 두 항목은 클립보드에 읽을 수 있는 그림이 있을 때만 켜진다.
- 대화상자 뒤 수식키 끼임: 단축키(Ctrl+Shift+V, Ctrl+O)로 메시지 상자·파일 대화상자를 띄우면 키를 떼는 신호는 대화상자가
  받는다. plat-win 은 WM_KILLFOCUS·WM_SETFOCUS 를 넘기지만, 잃고 되찾는 일이 한 프레임에 들어오면 ImGui 는
  `AppFocusLost` 가 거짓으로 끝나 키를 비우지 않는다. 그래서 Shift 가 눌린 채 남아 다음 Ctrl+Z 가 Ctrl+Shift+Z 로 보였다
  (2026-10-30 재현, Shift 를 한 번 눌렀다 떼면 풀렸다). lbx-gui 0.6.1 b5 에서 근본 수정했다: ImGui 에 넘긴 눌린 키를
  추적해 두고, 포커스를 잃으면 그 키와 수식키의 up 을 입력 큐에 순서대로 넣는다. 그래서 ltxm 에는 따로 대책을 두지
  않는다(처음 넣었던 대화상자 뒤 `ClearInputKeys` 는 걷어냈다).
- 단축키는 `ImGui::Shortcut(…, ImGuiInputFlags_RouteGlobal)` 으로 등록한다. 전역 경로는 순위가 가장 낮아, 글자 칸
  (JSON 창, DragFloat 를 Ctrl+클릭해 숫자를 치는 중 등)이 활성이면 그 칸이 등록한 Ctrl+C/V/Z/Y 가 이기고 이미지·래티스
  쪽으로는 오지 않는다. `io.WantTextInput` 을 직접 보던 방식은 키를 누가 가져갔는지 모르므로 쓰지 않는다. 조합은
  정확히 맞아야 하므로 Ctrl+O 와 Ctrl+Shift+O 가 섞이지 않는다. 끌기 도중(핀·DragFloat)에는 Undo/Redo 를 막는다.
- ImGui 의 클립보드는 글자 전용(`CF_UNICODETEXT`)이라 이미지는 Win32 클립보드 API 를 직접 쓴다. ltxm 은 Windows 전용이다. 다른 앱도 이미지
  클립보드가 필요해지면 plat 드라이버 서비스로 옮긴다.
- JSON 창 버퍼는 1 MB 로 늘리고, Apply Changes 는 JSON 이 객체로 읽힐 때만 적용한다.
- 드래그 앤 드롭은 plat-win 이 `WM_DROPFILES` 를 받지 않아 뒤로 미룬다(plat-win 수정과 체인 배포가 필요하다).

### 6-13. UI 문자열(다국어)

메뉴·대화상자 문자열은 코드 밖 JSON 으로 관리한다. 언어 하나가 파일 하나다(`bin/lang/<code>.json`, BOM 없는 UTF-8).

```json
{
    "language": "ko",
    "name": "한국어",
    "strings": {
        "menu.file": { "text": "파일", "desc": "Main menu: title of the File menu (file operations)" },
        "dlg.replace.size": { "text": "그림 크기가 바뀌었습니다: %d x %d -> %d x %d ...", "desc": "... Keep the four %d in this order" }
    }
}
```

- `language` = 언어 코드(파일 이름과 같다), `name` = 보기 > 언어 메뉴에 보일 이름(그 언어로 쓴다), `strings` = 키마다
  `text`(그 언어의 문자열)와 `desc`(번역자 참고: 어디에 나오는지, `%d` 가 무엇인지). `desc` 는 모든 파일에서 영어로 둔다.
- 새 언어는 `en.json` 을 복사해 `language`·`name` 을 바꾸고 `text` 만 옮기면 된다. 코드는 고치지 않는다.
- 찾는 순서: 고른 언어 → `en.json` → 키 자체(빠진 문자열이 화면에 키로 드러난다). `en.json` 이 기준 파일이다.
- 코드는 `TR("menu.file")`, 형식 문자열은 `TRF("paste.pos", x, y, w, h)` 로 쓴다(`ltxm_lang.h`). 키에 점이 들어가므로
  var 경로 찾기(`Find`) 대신 차례로 훑어 읽는다.
- 언어 고르기: 보기 > 언어. 고른 언어는 작업 폴더의 `ltxm_settings.json` 에 남는다. 처음에는 OS 화면 언어(`ko-KR` →
  `ko`)의 파일이 있으면 그것, 없으면 영어.
- lang 폴더는 작업 폴더에서 먼저 찾고, 없으면 실행 파일 옆에서 찾는다. 배포 묶음에 `lang/` 을 넣어야 한다.
- 메시지 상자는 UTF-8 → UTF-16 으로 바꿔 `MessageBoxW` 로 띄운다(A 판은 한글이 깨진다). 예/아니요/취소 단추는 Windows
  가 OS 언어로 쓴다.
- 1 단계 범위: 메뉴바 전체, 메시지 상자, 파일 대화상자 제목·거름 이름, 붙이기 안내. 창 제목(Texture Mapping Editor 등)은
  ImGui 가 이름으로 도킹 배치(`win0.ini`)를 기억하므로 바꾸면 사용자 배치가 한 번 풀린다 — `"번역###고정ID"` 로 옮길 때
  함께 정한다. 래티스·그리드 패널 안 문자열은 다음 단계.
- 한글 글리프: 글꼴은 `malgun.ttf`, ImGui 1.92 는 글리프를 쓰일 때 싣는다(범위 지정 불필요).

ltxm 정리(2026-10-29, 편집기 작업의 선행): svmdemo 에서 출발해 남아 있던 exe + `ltxm-core.dll` + `ltxm-ui.dll` 구조를
실행 파일 하나로 합쳤다(코어·UI 는 소스 파일 단위로만 나눔). lbsvm-core 의존은 이미 없었고(텍스처 맵 입출력은 사본),
lib/lbx 를 최신 main(v2.9.5, 7eaa1a87)으로 올렸다. 명령줄로 PNG 를 넘기면 시작할 때 연다.

lbx-geo 에 두는 이유: ltxm 과 lbsvm-core 가 같은 풀이를 써야 미리보기와 실제 화면이 같다. ltxm 의 텍스처 맵 입출력처럼
사본을 두면 어긋난다(지금 `ltxm_texmap.cpp` 가 lbsvm-core 사본이다).

ltxm 은 엔드유저에게 배포된 툴이다. E1 배포 전에 다음을 지킨다.
- 옛 PNG 를 열고 아무것도 안 고친 채 저장하면 `grids` 와 픽셀이 그대로여야 한다.
- 래티스를 만들지 않은 사용자에게는 화면과 저장 결과가 지금과 같다(Lattice 모드는 고를 때만 나타남).
- 릴리스 노트에 새 키(`lattices`)와 옛 소비자 영향 없음을 적는다.

## 10. 결정 사항 (2026-10-29)

1. **태그는 손잡이끼리 래티스 전체에서 유일**하다. 태그가 붙는 것은 손잡이뿐이고, 경계선과 기본 손잡이(형상으로 정해지는
   첫 선·끝 선)는 태그가 없다.
2. **`rep`(반복)는 v1 에서 자리만 둔다.** 쓰임새 후보는 타이어 자국 무늬처럼 경로를 따라 같은 무늬가 이어지는 띠다.
   가능 여부는 소비 쪽(SWEEP 띠 생성) 작업 때 확인한다.
3. **물리 단위는 래티스에서 뺀다.** `mm_per_px` 와 손잡이 `default` 를 없애고, 단위·`fix` 축척·기본 배치는 연결이 맡는다.
   지금 승용차 값은 기본 연결 파일(배포 자산의 가이드 정의)로 옮긴다(§3-1 끝).
4. **기본 손잡이·손잡이 하나뿐인 축은 초안대로**(§4 2 항).
5. **경계선을 지우면 합쳐진 구간은 `str`.** 양쪽이 같으면 그대로, 다르면 `str` 로 돌리고 알린다.
6. **`lbx_lattice` 는 lbx-geo 에 둔다.** 구조체·검사·풀이·변환은 var 없는 `lbx_lattice.c`, var ↔ 구조체는
   `lbx_lattice_var.c`(lbx-core C var API)로 나눈다.
7. **미리보기 프리셋**: E2 는 ltxm config 폴더 설정, E3 이후 연결 파일을 읽기 전용으로 열어 쓰기(§6-5).
8. **키 경계 샘플링**: 래티스 단위 선택 필드 `edge`(`hard`·`soft`). 없으면 쓰는 쪽 기본값. 선마다 두는 것은 쓰임새가
   더 생기면 검토한다.
9. **`seg` 값은 null·숫자·문자열**(초안 2). 값이 없으면 늘림, 숫자는 고정 길이의 배율, 문자열은 크기 변수 이름이다.
   이름을 붙이면 곧 고정이다. 크기 변수 값은 연결이 주며 여러 구간·두 축이 같은 이름을 쓸 수 있다(§3-2).
10. **대상 좌표계는 래티스에 저장하지 않는다.** 좌표계는 ISO 8855·화면 두 가지만 있는 것이 아니고, 래티스가 갖는
    사실은 "텍스처의 어느 방향이 대상의 +X(lon)·+Y(lat) 인가"(`axis`) 하나로 충분하다. 편집 화면은 원점 화살표에
    `+X`·`+Y` 를 달아 그 사실을 보여 주고, 미리보기의 보기 좌표계는 대상 시스템에서 원하는 방향으로 나오는지 확인하는
    편집기 세션 값이다. 미리보기에서 lon·lat 을 ±X·±Y 로 따로 고르던 선택은 없앴다(방향을 정하는 곳이 둘이 되므로).
